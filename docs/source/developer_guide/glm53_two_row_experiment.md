# 独立双行解码实验记录

**该实验的输出未通过同一模型单请求对照。** 此记录不改变现有单行多来源服务，正式路径继续使用已验证的 B1 R2 配方。本次在同一服务器上测量 TP1、DP8、EP8，MTP 关闭，每条请求 128 输入、128 输出，16 个客户端并发。双行实验每卡处理两条不同请求。

| 实现 | TPOT P50（ms/token） | 整机输出（token/s） | 解码（token/s） | 三轮真实 decode 观测 |
| --- | ---: | ---: | ---: | --- |
| 原生 graph 配置 | 19.899 | 753.567 | 803.359 | 6,095 graph，1 eager |
| 双行 MK 实验 | 33.969 | 446.548 | 470.712 | 6,096 真双行 MK |

完整计时的 48 条请求覆盖 381 个八 rank、十六请求的双行 epoch。相对原生，双行实验的整机输出吞吐下降 40.74%，请求 TPOT 增加 70.71%。独立的短输出审计中，有 30 个双行 epoch，42 层逐 token 路由证据覆盖 480/496 个转移，单目的卡最高 52 行。路由确实发生与输出正确分别验收。

## 生成精度

取 C16 第一波相同的 16 个输入，逐条在相同 DP rank 的 B1 模型重放。串行的 2,032/2,032 个 decode 步均执行 MK。16 条的完整输出全有分叉，逐位置只有 99/2,048 个 ID 相同。按请求 slot 排序的首次分叉（从 1 起计）为 1、1、1、3、2、2、2、2、3、4、2、2、3、2、2、1。前三波双行与原生 C16 比较时为 0/48 条整段相同，266/6,144 个输出位置相同。

有四条请求的首个输出已经不同，该 token 由原生 prefill 产生。另十二条首 token 相同的请求里，只有四条的第二个 token 也相同。原生自身在 C8 和 C16 的 24 个可对齐输入中，只有 8 个首 token 相同。这 8 个里仅 2 个第二 token 也相同。相反，重复运行的同模型 B1 前八个输入与早先 B1、早先真实 C8 均逐 token 一致。以上限定了归因范围，还需使用相同 KV、相同输入 token 和位置的单步对照区分原生 prefill、桥接状态及双行计算的贡献。

波级吞吐、全部请求的 TPOT、同 rank B1 逐输入分叉及三个对照轴见[可复算数据](glm53_two_row_experiment_data.json)。
